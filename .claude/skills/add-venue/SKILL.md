# Add a venue

Read `AGENTS.md` first (unknown is not zero, decimals only, no secrets, a fixture for every
parser). Start from an existing connector of the same kind:

| Kind | Template |
|---|---|
| CEX with REST + WebSocket book | `crates/adapters/src/deribit.rs` (+ `deribit_stream.rs`) |
| Onchain order book with a REST API | `crates/adapters/src/derive.rs`, `aevo.rs` |
| Onchain RFQ / signed maker orders | `crates/adapters/src/thetanuts.rs` |
| Onchain pool priced by a contract | `crates/adapters/src/hegic.rs`, `callput.rs` |
| Prediction-market binaries | `crates/adapters/src/kalshi.rs`, `limitless.rs` |

## 1. Platform id and registry

- Add the variant to `PlatformId` and to `PlatformId::ALL` (`crates/core/src/domain.rs`).
- Add a `PlatformInfo` entry in `crates/adapters/src/registry.rs`: networks, capabilities (what the
  platform offers), the official sources you actually read, `verified_on`, and `notes` stating what
  is integrated and what is missing.

## 2. Record real responses

Call the venue's **public** endpoints (catalog, order book, fees if published) and save the raw
answers under `fixtures/recorded-<YYYY-MM-DD>/<venue>_*.json`. No account data, no keys.

## 3. Connector

Create `crates/adapters/src/<venue>.rs` implementing `Connector` (`crates/adapters/src/lib.rs`):

- `list_instruments`: map each native instrument to `Instrument` / `InstrumentKey`. Fill every
  contract term you can source (expiry instant in UTC, settlement asset, index and window, premium
  currency, multiplier, exercise style). Leave the others `None`: they then surface as differences,
  which is correct.
- `get_market_data`: book levels as `Decimal`, using the shared helpers in `lib.rs`
  (`pair_levels`, `ts_ms`, `MarketData::rest`) and `http::get_json`.
- `get_fees`: the published formula with its source. Not published: `FeeAmount::Unknown` with the
  reason; the venue is then shown but never routed.
- USDT-quoted venue: wrap it in `UsdtAsUsdc` when attaching it.
- Tests in the same file, against the fixtures (`fixture()` helper): parsing, units, edge cases
  (empty book, expired instrument, unknown fields).

Declare the module in `crates/adapters/src/lib.rs`.

## 4. Attach it

Add it to the connector list in `crates/app/src/bin/server.rs` (the mainnet read-only list; the
testnet list only if the venue has a test network). Geo restrictions in the venue's terms go to
`config/geo-policy.json`, with the source of the rule.

## 5. Optional: non-custodial execution

Create `crates/adapters/src/<venue>_user.rs` implementing `ExecutionVenue`
(`crates/adapters/src/exec.rs`):

- build the exact payload the user signs (EIP-712, SNIP-12 or a transaction) from the order;
- `check_user_signatures`: recover the signer and compare it with the declared account **before**
  anything is sent; refuse stale timestamps and expired signatures;
- `submit`: forward the signed order, or verify the public receipt (contract, calldata, sender);
  map the answer to `VenueOrderState` and never treat an unknown status as final;
- `identity()` reports `"custody": "NON_CUSTODIAL"` and the signing `chain_id`;
- prove it with a reference vector generated by the venue's own SDK (`fixtures/<venue>_vector.json`,
  generator in `scripts/`) and a refusal test (wrong signer);
- parse the user's account in `ExecutionService::prepare_user_signed`
  (`crates/app/src/execution.rs`) and add the opt-in switch `OA_<VENUE>_NONCUSTODIAL` in
  `bin/server.rs`.

## 6. Finish

- Update the venue table in `README.md` (and in the translated READMEs if you can) and
  `docs/integrators.md` for execution formats.
- Run the `verify` skill.
